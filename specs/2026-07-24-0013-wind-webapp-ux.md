# 0013 — Wind in the webapp (UX)

- **Status:** Accepted
- **Date:** 2026-07-24
- **Authors:** Hadrien Mary (+ Claude)
- **Relates to:** [0012 wind](2026-07-24-0012-wind.md) (the data layer this surfaces — Phase 2/3 of that
  spec), [0008 tides](2026-07-05-0008-tides.md) (the per-place, shared-across-buoys pattern the
  station reuses), [0005 multi-buoy](2026-06-27-0005-multi-buoy.md) (selection + persistence), [0006
  stack/a11y](2026-06-28-0006-stack-migration-a11y.md) (Tailwind tokens, Paraglide, uPlot).

> Surface **wind (vent)** in the webapp beside each buoy. The organizing idea is a single visual
> axis — every datum belongs to a **realm**: **Mer** (the buoy, offshore: swell, direction, sea
> temp — teal) or **Air** (the station, onshore: wind, gust, air temp, rain — amber). Colour **+**
> glyph, constant across all three surfaces (selection · current conditions · timeseries), so
> "buoy" vs "station" reads at a glance. The single synthesized payoff is **offshore / onshore**
> (station `wind_direction_deg` × buoy `peak_direction_deg`).

---

## 1. The realm system (the spine)

Provenance is the primary visual axis, orthogonal to which metric it is. Two realms, each with a
**colour + an icon**, applied identically everywhere:

| Realm | What / where | Colour token | Icon |
|-------|--------------|--------------|------|
| **Mer** (buoy) | swell, peak direction, sea temp — *offshore* | `--accent` teal (existing) | buoy glyph |
| **Air** (station) | wind, gust, air temp, rain, humidity, pressure — *onshore, X km away* | **`--c-wind` amber** (new) | anemometer/station glyph |

- **Amber** (dark `#f4b740`, light `#a06600`) was chosen for the Air realm: the cool palette is
  already crowded (teal=height, sky=period, indigo=tide, lilac=swell-dir), so a **warm** hue gives
  the cleanest pre-attentive "air vs sea" split. It is distinct from `--c-temp` orange because the
  **realm glyph + zone**, never colour alone, carry provenance (see the temperature rule below).
- Colour is the fast hint; the **glyph** is the confirmation. Both are constant across surfaces.
- The Air realm colour also matches the ingest CLI (`ui.WIND` / `ICON_WIND`) — one system end to end.

## 2. Decisions

### 2.1 Selection — buoy (primary) + station (override), keep the fold
- The existing **collapsible StationBar is kept** (fold state `olatu.station_collapsed`, segmented
  buoy control, lazy MapLibre locator, CANDHIS/HF source links, intro copy). Wind is **added**, not
  a rewrite.
- A **station picker** sits in the Air realm (amber pill: `⌂ Socoa · 1.6 km`, character +
  attribution). **Default = the buoy manifest's `wind` pointer** (nearest curated station). The user
  may pick any curated station; the pairing is **persisted per buoy** in `olatu.station`
  (`{ "06403": "biarritz-pays-basque" }`), default wins when a buoy has no stored override.
- The **locator map** gains station markers (amber, square = "instrument on land") and a **dashed
  pairing line** buoy↔station with the distance — the pairing becomes spatial.
- Honesty (spec 0012 §4): the station is always named **+ its distance + character** ("sémaphore
  côtier 21 m" / "aéroport, plateau 71 m"), never "the wind at the buoy".

### 2.2 Current conditions — two zones + a bridge (owner-chosen)
Keep the section compact; **two clearly-separated realm zones** stacked, joined by one cross-realm
bridge:
- **Mer zone** (teal header `MER · <buoy> · CANDHIS`): the existing swell compass (dir + spread
  cone, `dirColor` hue), the hero **Hs**, gauges [Hmax · période · **temp mer** (teal)].
- **Bridge** (the only cross-realm element): mini swell arrow (teal) **vs** mini wind arrow (amber)
  → the **offshore / onshore verdict** badge (see 2.3). Lives *between* the zones because it needs
  both.
- **Air zone** (amber header `AIR · station <name> · <km> · Météo-France`): a wind compass (from-dir
  + gust marker, amber), gauges [vent · rafale · **temp air** (amber) · pluie], and a secondary row
  [humidité · pression] (both **nullable** → em-dash empty-state, e.g. Cap-Ferret).
- **TideStrip is kept** at the bottom of the card unchanged; staleness badge + InfoPopovers kept.
- **The temperature rule** (owner's explicit pain point): sea temp lives in the teal zone, air temp
  in the amber zone; each carries its realm glyph + an explicit `Mer`/`Air` micro-label. Provenance
  is zone + glyph + colour together — **never colour alone**. Same logic disambiguates swell
  direction (Mer compass) from wind direction (Air compass).

### 2.3 Offshore / onshore (the synthesized payoff)
- Verdict from the angle between the station's `wind_direction_deg` (where wind blows **from**) and
  the buoy's `peak_direction_deg` (where swell comes **from**): `d = wrap180(|wind − swell|)`.
  **d ≥ ~135° → OFFSHORE** (wind opposes the swell → clean), **d ≤ ~45° → ONSHORE** (blown out),
  else **CROSS / SIDE-SHORE**. Semantic colours: offshore `--calm` green, onshore `--danger`, cross
  `--warning` — distinct from the realm accents.
- **Honest approximation**: this uses the swell bearing as a proxy for beach orientation ("the beach
  faces the swell"). Good enough as a headline; a per-buoy `shore_normal_deg` can refine it later
  (open item). Needs both feeds present → empty-state when either is missing.

### 2.4 Timeseries — station beside buoy, hide/reorder, persisted
- Wind panels join the uPlot stack on the **exact same X-axis + cursor** as the buoy panels (the
  tide panel already proves a panel can carry its own time grid while staying `cursor.sync`'d — the
  wind station is on a different cadence). Wind panels: **vent** (mean + gust), **direction vent**
  (glyph arrow row, reusing `drawArrowGlyphs`, shape distinct from swell), **température air + mer**
  (one panel, two lines — sea teal, air amber — the land/sea relationship), **pluie**, and
  optionally humidité/pression.
- Each panel is **realm-tagged**: a coloured left edge + a `Mer · bouée` / `Air · station` chip in
  the header, so a long stack still reads sea-vs-air at a glance.
- **Hide + reorder** (owner-chosen: drag + eye + chips): every panel header gets a **drag handle**
  (HTML5 DnD, no new dep) and an **eye** toggle; hidden panels collapse into a compact **chip tray**
  above the stack, click-to-restore.
- **Persistence** (firm requirement): `olatu.charts.order` (panel id order) + `olatu.charts.hidden`
  (hidden ids), tolerant to future panels (unknown ids append). Existing persisted state kept:
  `olatu.campaign`, `olatu.range`, `olatu.smooth`, `olatu.station_collapsed`, `olatu.theme`.

### 2.5 Data contract consumed (already shipped by spec 0012)
- Buoy `manifest.json` carries a `wind` **pointer**: `{ station, num_poste, label, distance_km,
  source }` (null when no station in range → wind empty-state).
- Each station is a **buoy-shaped tiered dataset** at `wind/<station>/data/` (`manifest.json` +
  `latest`/`recent`.json + `year/`, `hourly/` parquet + `daily.parquet`), loaded with the **same
  code path** as a buoy — only the base URL differs (`windBase(station) = DATA_ROOT +
  wind/<station>/data/`, symmetric with `tidesBase`). 8 vars; `humidity_pct`/`pressure_msl_hpa`
  nullable. Units m/s, °, °C, mm, %, hPa (convert for display later; display units are a separate
  polish, out of scope here).

## 3. New / touched code

- **`styles.css`** — `--c-wind` (+ `--color-wind` bridge), both themes.
- **`icons.tsx`** — `wind`, `station`, `eye`, `grip` glyphs (custom SVG family, `iconSvg` too).
- **`lib/data.ts`** — `WindMeta` + `Manifest.wind`; `windBase(station)`; station-parameterized JSON
  + parquet loaders (or wind variants); `loadWindStation(...)`.
- **`lib/stations.ts`** (new) — curated station registry (id, label, character, lat/lon, altitude) +
  `olatu.station` per-buoy override helpers (mirror of `buoys.ts`).
- **`lib/wind.ts`** (new) — offshore/onshore model + display helpers (from-compass reuse).
- **`components/CurrentConditions.tsx`** — two-zone rebuild (Mer + bridge + Air), keep tide/staleness.
- **`components/StationBar.tsx`** + **`BuoyLocator.tsx`** — station picker (keep fold) + map pairing.
- **`components/TimeSeries.tsx`** — wind panels, realm tags, hide/reorder + chip tray, persistence.
- **`App.tsx`** — load the paired station's tiers (race-tagged like `tides`/`history`), station
  override state, thread props.
- **Paraglide `messages/{en,fr,es}.json`** — new keys (`cc_air*`, `cc_offshore*`, `def_wind*`,
  station picker, chart titles/realm labels).

## 4. Plan

- **Phase A — foundation:** tokens + icons + data types/loaders + stations registry + wind lib +
  i18n. Build stays green (nothing wired yet).
- **Phase B — wiring:** `App.tsx` loads the paired station and passes it down.
- **Phase C — current conditions:** the two-zone card + offshore/onshore.
- **Phase D — selection:** the station picker + map pairing (fold preserved).
- **Phase E — timeseries:** wind panels + hide/reorder + persistence.
- Iterate on polish afterwards (owner: "on itérera si besoin").
