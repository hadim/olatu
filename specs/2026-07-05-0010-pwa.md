> Owner request: *"add a PWA so people can install it as an app on a tablet or phone
> (Android or Apple)."* Make the static site installable ("Add to Home Screen") and give it
> an offline shell, without disturbing the every-30-min live-data model.

---

## 1. Goal & scope

Olatu is already a fully static site on GitHub Pages that reads its data tiers from the HF
bucket at runtime. A PWA layer makes it **installable** on Android (Chrome), iOS/iPadOS
(Safari → Add to Home Screen), and desktop, and gives it a **cached app shell** so it opens
instantly and degrades gracefully offline.

**In scope:** web app manifest, icons (incl. maskable + apple-touch), a Workbox service
worker (precache + runtime caching), iOS standalone hints, silent auto-update.

**Out of scope (deliberately):** push notifications, background sync, an in-app "update
available" toast (we auto-update silently instead), and any offline write/queue — Olatu is
read-only. Full offline history charts are **not** guaranteed (see §4).

## 2. Tooling decision — `vite-plugin-pwa`

Use **`vite-plugin-pwa`** (Workbox `generateSW` mode) + **`@vite-pwa/assets-generator`**.

- It slots into the existing Vite build; CI (`npm ci && npm run build`) needs no new steps.
- `generateSW` (vs `injectManifest`) keeps us out of hand-written service-worker code — we
  only declare a manifest + runtime-caching rules.
- Relative `base: './'` (kept, so one build serves both the apex `olatu.io` and the project
  path `hadim.github.io/olatu/`) flows through to the injected `registerSW.js` and the
  manifest link — `%BASE_URL%` → `./`, so the SW scope resolves per-origin automatically.

## 3. Icons — generated once, committed

- Source: **`webapp/public/pwa-icon.svg`** — the same "O" wave-barrel monogram as
  `favicon.svg` / `components/brands.tsx <Logo>`, but **full-bleed** (square, no rounded
  corners) on the dark canvas `#0A1622`, so maskable/apple crops stay on-brand (the OS
  applies its own corner mask). **Keep all three in sync.**
- **`webapp/pwa-assets.config.ts`** (preset-style) drives `@vite-pwa/assets-generator`
  (`npm run pwa-assets`) → emits into `public/`: `pwa-64/192/512.png` (transparent preset =
  solid dark tiles, serve as `any`), `maskable-icon-512x512.png` (padding 0.1, dark bg so
  the "O" stays inside the safe zone), `apple-touch-icon-180x180.png` (padding 0.06), and
  `favicon-48.png`.
- **Decision: the generated PNGs are committed** (not built in CI). This keeps the GitHub
  Pages build deterministic and **free of a `sharp` dependency**. Regenerate only when the
  logo changes (`npm run pwa-assets`). The manifest's icon list (in `vite.config.js`) and
  the `apple-touch-icon` `<link>` (in `index.html`) reference these filenames by hand.

## 4. Caching strategy — live-first, offline-tolerant

The key constraint: the app **polls `manifest.json` every 5 min** and pulls fresh
`latest`/`recent` when `generated_at` advances (specs/0004). The SW must never make data go
stale. Rules (`workbox.runtimeCaching`, all `cacheableResponse: [0, 200]`):

| Target | Strategy | Rationale |
|---|---|---|
| App shell (JS/CSS/HTML/icons, `globPatterns`) | **Precache** + `autoUpdate` | instant open; refreshed on each deploy |
| HF bucket data (`huggingface.co` + `/buckets/hadim/olatu/resolve/`) | **NetworkFirst** (`olatu-data`, 6 s timeout, 7-day/64-entry cap) | online → always live; offline → last-known JSON |
| `fonts.googleapis.com` | StaleWhileRevalidate | |
| `fonts.gstatic.com` | CacheFirst (1 yr) | font files are immutable |
| MapLibre tiles (external) | *(no rule → passthrough)* | respect the tile provider; don't bulk-cache |

- **`og.png` (112 KB link-preview) and `pwa-icon.svg` (the icon source) are excluded from
  precache** (`globIgnores`) — neither is needed offline.
- **Offline reality:** the current-conditions **banner works offline** (its JSON tiers are
  200s and get cached). History **charts are best-effort** — parquet fetched via HTTP range
  returns **206 Partial Content**, which Workbox does not cache; full-GET parquet (200) is
  cached. We accept this rather than force full downloads. This mirrors the app's existing
  empty-state handling for missing data, so no new UI is needed.

## 5. Update model — silent `autoUpdate`

`registerType: 'autoUpdate'` (skipWaiting + clientsClaim → reload when a new SW takes
control). A data-viz dashboard should always show the latest build; a manual "reload to
update" prompt adds friction for no benefit here. `cleanupOutdatedCaches: true` prunes old
precaches. `injectRegister: 'auto'` means **no app-code change** — `main.tsx` is untouched;
the plugin injects `registerSW.js`. `devOptions.enabled: false` keeps `pixi run webapp`
(dev) clean; the SW is exercised via `npm run build && npm run preview`.

## 6. Manifest

`display: standalone`, `theme_color`/`background_color: #0a1622` (the dark canvas, matching
the existing `theme-color` metas), `start_url`/`scope: '.'` (relative → correct at both the
apex and the project path), `categories: [weather, sports, utilities]`, `orientation: any`,
`lang: en`, a `wide` screenshot (reusing `og.png`). iOS, which ignores the manifest, gets
`apple-mobile-web-app-capable` / `-title` / `-status-bar-style: black-translucent`
(+ `mobile-web-app-capable`) and the raster `apple-touch-icon` in `index.html`.
